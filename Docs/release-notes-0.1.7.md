# SwiftDown 0.1.7

## 新增：预览里能直接改字

预览不再是「只读」。鼠标停在任意一块上，右上角出现一支铅笔，点开就在原地改这一块的
Markdown 源码，`⌘↩` 完成、`Esc` 取消。标题、段落、代码块、列表、表格、引用都支持。

### 为什么改的是「源码」而不是所见即所得

所见即所得要把光标位置映射回源文本的字符区间。软换行、行内代码、链接嵌套会让这个映射变成
一个小型编译器，而映射错一位就是把用户的 `**粗体**` 写成乱码——**失败代价是文档被写坏**。
源码编辑最差只是「看着不像预览」，但绝不会写出语义错误的东西：框里写的是什么，原文里就正好是
那一段，一次只动这一段。

所以你会看到 `## 标题` 和 `**强调**` 的原样写法。这是刻意的取舍，不是没做完。

### 三个细节

1. **不多吃一行空行**。块的结束位置取「下一块的起始行 − 1」，再把尾部空行削掉。
   不削的话块与块之间的空行会被卷进编辑区，提交时一起重写——你只改一个错别字，
   diff 里却凭空多出空行的增删。
2. **撤销能撤回去**。拆分模式下走编辑器的标准编辑路径，撤销由编辑器登记；仅预览模式下没有
   编辑器，会在撤销栈上补一步，`⌘Z` 一样能退。改动进入「未保存」状态，存盘规则不变。
3. **不覆盖别人的改动**。提交前会核对「这一段原文还是不是打开编辑框时那一份」。拆分模式下
   你可能同时在左边敲字，位置已经对不上了——这时宁可放弃这次写入，也不会把别处的改动冲掉。

## 修复：鼠标停在代码块上滚轮不动

代码块原来是「横向 ScrollView 套在纵向 ScrollView 里」。嵌套滚动容器是滚轮事件最经典的坑：
内层能消化滚动，纵向滚轮就被它先吃掉，既不滚自己（它是横向的）也不往外交，页面就卡住了。

改成自建的横向滚动容器，按主导轴分流：竖向为主的滚轮交给外层页面，横向为主的才自己滚。
长行还是不换行、可以横向拖着看，选中和复制也照旧。

> 说明：这一项我做了结构性的修改，但**合成事件验不出真实手感**（把旧实现放回去，
> 合成滚轮事件同样能滚页面）。真机手感需要你自己滚一下确认，我不想把没验过的事说成验过了。

## 顺带

- 代码块的语法着色换成 AppKit 出口后，与正文高亮共用同一份词法分类，不会再出现
  「改了一处、另一处还是旧颜色」。
- 预览代码块的高度改成按行数直接算（`行数 × 行高 + 内边距`），不再依赖 SwiftUI 的尺寸回询，
  打开文档时不会先闪一下矮框。
