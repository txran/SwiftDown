# SwiftDown 0.1.9 发行说明

预览里改字时**看不到任何源码标记**了。点进去看到的就是排版后的样子，
不再出现 `## ` 或 `**`，也不再整块变个底色告诉你「进入编辑模式了」。

## 改了什么

上一版的规则是「标记只在光标所在行显形」。听起来合理，用起来不对：
标题、单行段落、列表项都是**单行块**，光标行就是整块——点一下 `阅读模式`，
屏幕上立刻冒出 `## `，看上去就是切到了源码。

现在：

- **行内标记永久透明**：`**` `` ` `` `[..](..)` 在任何情况下都不显示。
- **标题的 `#` 也藏掉**：渲染态标题本来没有缩进，藏掉之后文字起点才对得齐。
- **列表的 `-`、引用的 `>` 保留淡显**：它们同时是行首缩进的替身，藏掉会让这一行整块左移。
- **编辑态不铺底色、不加边框**，和渲染态是同一个东西，只是多了个光标。
- **光标进不去隐藏的标记**：方向键、点击都不会停在看不见的字符上，退格也不会删掉半个 `**`。
- **点标题时整块不会跳**：补齐了标题的上留白，高度也改用「行片求和」来量。

改样式（加粗、改标题层级、插链接、改列表层级）仍然回源码模式——预览里改的是字。

## 修掉的两个真实缺陷

- **标题进编辑时块高矮 4~10pt、字底部被切一条**。块高用的是 `usedRect`
  （字形外接框）：纯中文行没有下伸部，行距也不在它的口径里。改成逐行 `lineFragmentRect` 求和。
- **光标能停在透明标记上**。这是上一版就有的问题，这次靠「跳过隐藏区间」堵上了。

## 仍然是已知限制

- **表格**点进去看到的是 `| a | b |` 原始写法（不在预览里画成表格，目前只能这样改）。
- **纯图片段落**（`![](pic.png)` 独占一段）整段只有标记，会退回显示原始写法，
  否则点进去是个空框。
- 长段落折行后，点击落点与光标位置可能差几个字（排版是离线估算的）。
- 中文大字号（标题）在预览与编辑之间有约 4pt 的行高差——中文 26pt 会被系统替换成
  PingFang Display，行高比西文字体算出来的小，属字体替换差异。

## 自检

187 → **193 项全通过**。这一轮的关键断言：标记始终透明、标题井号透明而标题文字不变、
列表符号淡显且不算隐藏字符、整块只有标记时改淡显、
**真文本视图里把光标塞进隐藏区间确认被推到边界**、标题块进编辑前后高度一致。
