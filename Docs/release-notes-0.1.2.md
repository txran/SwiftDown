# SwiftDown 0.1.2（打开文件不再卡顿）

## 修了什么

**现象**：运行中打开另一个 Markdown，窗口像「关掉又重开」，大文件尤其明显。

**这次量出来了**：打开 4.8MB（330 万字符）的文档，主线程被**整整阻塞 2.5 秒**。
这 2.5 秒里一帧都不出，窗口就是「死的」，等它结束内容才一次性换上去 —— 这就是
「像关闭又重新打开」的来源。

卡顿全部来自**全文语法高亮**：`MarkdownHighlighter` 对整篇文档做行扫描 + 正则着色，
330 万字符一次 2.5 秒。

**改法**：

- 大文档（超过 20 万字符）只高亮当前可见区，滚动时按需补刷，不再全文扫
- 换文档时正文先上屏（实测约 15ms），语法着色推迟到下一轮 runloop
  （TextKit 2 对超长文本首次写属性有一次性索引开销，实测约 220ms，放到上屏之后用户就看不到了）
- 围栏代码块的「进没进围栏」判断原本要从文档头扫到目标位置，大文档滚到末尾时单独就要一秒；
  现在只回溯最近 256KB

**结果**：同一份 4.8MB 文档，从命中 `open` 到内容上屏 **2548ms → 51ms**。

## 顺带查清的事实

用帧级探针（主 runloop 每次 `beforeWaiting` 采样窗口状态 + 编辑器实例 + 内容区像素）确认：

- 打开文件时窗口从未被重新 order front：`alpha` 恒为 1、`isVisible` 恒为 1、窗口号不变
- 编辑器 `NSTextView` 自始至终是同一个实例，不存在销毁重建
- 内容区像素没有出现白帧/空白帧

也就是说 0.1.1 去掉 `.id(tab.id)` 之后，视图层已经是干净的；0.1.2 解决的是「主线程被高亮按死」。
如果你的使用场景里仍能看到闪，那就是 macOS 在把应用从后台切到前台时的窗口过渡
（所有应用都有，TextEdit 也一样），这一层 app 无法左右。

## 验证

- `--selftest` 72 项断言全 PASS
- 新增回归保护：换文档后文本区宽度必须等于可视宽度（标尺变宽时首行不被压住）——
  这一条在开发过程中真的抓到了我一次改动顺序错误
- 打包后解压实跑自检，全部 PASS
