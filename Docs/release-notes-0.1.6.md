# SwiftDown 0.1.6

## 新增：全局查找与替换，快捷键可在设置里改

`⌘F` 查找、`⌘⌥F` 展开替换。两个范围：

- **当前文档**：全文查找（不是只查可见区），`1/3` 计数、上下跳转、可替换。
- **所有标签**：跨已打开文件列出「文件 → 行号 → 片段」，点一下跳过去。替换只在当前文档范围开放。

选项三个开关：区分大小写、整词、正则。快捷键默认 `⌘F` / `⌘G` / `⇧⌘G` / `⌥⌘F`，
在「设置 · 快捷键 · 查找」里可改，冲突会自动拦下。

### 为什么没有沿用系统查找栏

`NSTextView` 自带查找栏，两个硬伤：**它的 ⌘F 改不了**（AppKit 内建，接不进可配置的快捷键体系），
**它只搜当前这一个 `NSTextView`**（跨文件搜索得自己来）。所以把 `usesFindBar` 关掉了——
不关的话同一条 `⌘F` 会同时唤出两套界面。

### 三个实现上的取舍

1. **高亮不写进文本**。写 textStorage 会污染撤销栈（⌘Z 撤销的不是你的编辑）、触发自动保存、
   还会被语法高亮覆盖。改用引擎的渲染属性层（TextKit 2 的 `addRenderingAttribute` /
   TextKit 1 的 `setTemporaryAttributes`），只影响绘制。
2. **替换走 `insertText(_:replacementRange:)`**。这是 `NSTextView` 的正规编辑入口，
   撤销注册与委托通知都由它完成。批量替换倒序执行并套一层撤销分组，**N 次替换 = 1 步撤销**。
3. **跳转不抢焦点**。`⌘F` 打完字焦点还在输入框里，跳转只滚动 + 选中 + 系统查找指示器。

当前命中用实色高亮，其余压到 35%。像素实测：当前处 sRGB ≈ 1.00/0.98/0.35，其余 ≈ 1.00/0.99/0.79，
屏幕上确实分得开。

## 修复：两个本轮抓到的真问题

| 现象 | 真因 | 修法 |
|---|---|---|
| 正则 `^dog` 搜不到第 2 行行首 | `NSRegularExpression` 默认只认整段文本首尾，不带 `.anchorsMatchLines` 时 `^` 不匹配每行行首 | 构造 options 时默认加上 |
| 替换栏浮在编辑区半空，还顶出一大块空白 | 左侧占位用了 `Color.clear.frame(width:)`——`Color` 两个轴都贪婪，宽度定住而高度没定，整行被撑满、同行控件垂直居中 | 换 `Spacer().frame(width:)`，并补一条固有高度断言 |

第二个问题**单看查找栏截图是看不出来的**：截图时 host 高度被写死，错误被掩盖。
把查找栏放回真实窗口渲成整窗图才看见它根本没贴着编辑区。

## 自检

134 项全 PASS（0.1.5 为 82 项），新增 52 条，其中 20 条是这次查找替换的。

值得单独说的是一组**像素级断言**。高亮是 TextKit 的渲染属性，不进 `textStorage`，
所以「区间算对了」证明不了「屏幕上有颜色」——这是整个功能里唯一「模型全对、用户可能什么都看不见」的地方。
做法是把探针 `NSTextView` 离屏渲成位图，数「偏黄」像素并按饱和度分档：

| 状态 | 实色 px | 淡色 px |
|---|---|---|
| 未查找 | 0 | 0 |
| 1 处命中 | 298 | 0 |
| 3 处命中（当前 = 第 1 处） | 298 | 569 |
| 清除后 | 0 | 0 |

`298×3 ≈ 298+569`，且实色恰好等于「一处」的量——一次证明三件事：每处都画了、
当前处与其余处层级真的分开、清除是干净的。TextKit 2 与显式降级后的 TextKit 1 各跑一遍，数字一致。

另有两条布局断言（查找栏两行 68pt、菜单里 `⌘F` 全局只有一项）兜住「看得见但断言不到」的错。

## 安装

下载 `SwiftDown-0.1.6-arm64.dmg`，拖进「应用程序」。首次打开若提示无法验证开发者，
右键 → 打开，或执行：

```bash
xattr -dr com.apple.quarantine /Applications/SwiftDown.app
```

仅 Apple Silicon（arm64），macOS 13+。
