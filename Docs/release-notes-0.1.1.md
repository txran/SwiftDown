# SwiftDown 0.1.1（修复「打开文件闪一下」）

本次只做一件事：把运行中打开另一个 Markdown 时的闪屏修掉。功能与 0.1.0 一致。

## 修了什么

**问题**：应用运行时从访达双击另一个 `.md`，窗口会闪一下。

**原因**：切换文档时编辑器视图被整个销毁重建。`RootView` 上挂了 `.id(tab.id)`，
每次打开/切换文档都会改变视图身份，于是 `NSScrollView` / `NSTextView` / 行号标尺全部重建，
「旧的已拆、新的未挂」之间漏出一帧空白。TextEdit、VS Code 这类编辑器不闪，
是因为它们切换文档时从不销毁编辑器，只替换文本。

**改法**：编辑器实例常驻，切换只换内容——与成熟编辑器的做法一致。

- 换文档时替换文本存储、重刷高亮、复位选区与滚动
- 撤销栈按文档清空（否则 ⌘Z 会撤销出上一个文档的内容）
- 行号栏宽度改为在换文档时主动重算，避免「标尺变宽」比「文本重排」晚一帧造成横向跳动
- 状态回写（当前行）推迟到布局结束之后，避免在 SwiftUI 布局期改状态导致的重绘抖动

## 顺带说明

上一版曾把这个现象判断为「macOS 的应用激活过渡」，依据是截屏连拍。那个判断是错的：
截屏单帧耗时在百毫秒量级，而一帧空白只有约 16.7ms，采样根本抓不到。
这次改用「视图实例是否被销毁」来定位，并把结论写成了自检断言。

## 验证

- `--selftest` 72 项断言全 PASS（0.1.0 为 65 项，新增 7 项覆盖本次修复）
- 新增断言：切换文档前后 `NSTextView` 必须是同一个实例、行号栏随行数位数变宽（46→50）、
  文本区宽度贴合可视宽度（首行不被行号遮住）、切换后行号仍连续
- 把 `.id(tab.id)` 加回去，这组断言会立即 FAIL——断言有效性已反向验证
- 本发行包已解压后实跑自检，全部 PASS
